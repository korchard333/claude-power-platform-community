# Plugins — Project Setup & Architecture

## Project Setup

### Create Plugin Project
```bash
# Create solution and project
mkdir ContosoPlugins && cd ContosoPlugins
dotnet new classlib -f net462 --name Contoso.Plugins
cd Contoso.Plugins

# Add required NuGet packages
dotnet add package Microsoft.CrmSdk.CoreAssemblies    # IPlugin, IOrganizationService
dotnet add package Microsoft.CrmSdk.XrmTooling.CoreAssembly  # Optional: for tool integration

# For unit testing
cd .. && dotnet new xunit --name Contoso.Plugins.Tests
cd Contoso.Plugins.Tests
dotnet add package FakeXrmEasy.v9   # Dataverse mocking framework
dotnet add reference ../Contoso.Plugins/Contoso.Plugins.csproj
```

### Project File (.csproj)
```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net462</TargetFramework>
    <AssemblyVersion>1.0.0.0</AssemblyVersion>
    <FileVersion>1.0.0.0</FileVersion>
    <SignAssembly>true</SignAssembly>
    <AssemblyOriginatorKeyFile>ContosoPlugins.snk</AssemblyOriginatorKeyFile>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Microsoft.CrmSdk.CoreAssemblies" Version="9.0.*" />
  </ItemGroup>
</Project>
```

### Strong Name Key (Required for Plugin Registration)

#### Windows
```bash
# Generate signing key (Windows — requires .NET SDK or Windows SDK)
sn -k ContosoPlugins.snk
```

#### macOS / Linux (sn.exe unavailable)
`sn.exe` is Windows-only. Generate an SNK via a temporary .NET console app:

```bash
# Create a temp project
mkdir /tmp/snkgen && cd /tmp/snkgen
dotnet new console -f net10.0

# Replace Program.cs with this one-liner
cat > Program.cs << 'EOF'
using System.Security.Cryptography;
var csp = new RSACryptoServiceProvider(1024);
File.WriteAllBytes("ContosoPlugins.snk", csp.ExportCspBlob(true));
Console.WriteLine("SNK written to ContosoPlugins.snk");
EOF

dotnet run
# Copy the generated ContosoPlugins.snk to your plugin project
```

## Plugin Architecture

### Execution Pipeline
```
Client Request (Create/Update/Delete/Custom API)
  │
  ├── Stage 10: Pre-Validation
  │     └── Runs BEFORE security checks
  │     └── Use for: input validation, early rejection
  │     └── Transaction: NOT in database transaction
  │
  ├── Stage 20: Pre-Operation
  │     └── Runs AFTER security, BEFORE database write
  │     └── Use for: default values, auto-numbering, field transformation
  │     └── Transaction: IN database transaction (can roll back)
  │
  ├── [Database Operation]
  │
  ├── Stage 40: Post-Operation (Sync)
  │     └── Runs AFTER database write, SAME transaction
  │     └── Use for: cascading updates, cross-entity logic
  │     └── Transaction: IN database transaction (rollback undoes the trigger operation too)
  │
  └── Stage 40: Post-Operation (Async)
        └── Runs AFTER transaction commits, in background
        └── Use for: notifications, logging, long-running tasks
        └── Transaction: SEPARATE transaction (can't roll back trigger)
```

### IPlugin Interface (Basic Template)

> **Tip:** For new projects, consider using the **PluginBase abstract class** (generated by `pac plugin init` or Power Platform Tools for Visual Studio), which reduces boilerplate. See the PluginBase section below for details.
```csharp
using System;
using Microsoft.Xrm.Sdk;

namespace Contoso.Plugins
{
    public class SetDefaultPriority : IPlugin
    {
        // Unsecure/Secure configuration from plugin registration
        private readonly string _unsecureConfig;
        private readonly string _secureConfig;

        public SetDefaultPriority(string unsecureConfig, string secureConfig)
        {
            _unsecureConfig = unsecureConfig;
            _secureConfig = secureConfig;
        }

        public void Execute(IServiceProvider serviceProvider)
        {
            // 1. Get execution context
            var context = (IPluginExecutionContext)serviceProvider
                .GetService(typeof(IPluginExecutionContext));

            // 2. Get tracing service (for debugging)
            var tracingService = (ITracingService)serviceProvider
                .GetService(typeof(ITracingService));

            // 3. Get organization service (for CRUD operations)
            var serviceFactory = (IOrganizationServiceFactory)serviceProvider
                .GetService(typeof(IOrganizationServiceFactory));
            var service = serviceFactory.CreateOrganizationService(context.UserId);
            // Use null for system context: serviceFactory.CreateOrganizationService(null);

            try
            {
                // 4. Validate the context
                if (context.InputParameters.Contains("Target")
                    && context.InputParameters["Target"] is Entity target)
                {
                    tracingService.Trace("Plugin executing for {0}", target.LogicalName);

                    // 5. Business logic
                    if (!target.Contains("contoso_priority"))
                    {
                        target["contoso_priority"] = new OptionSetValue(100000001); // Medium
                        tracingService.Trace("Set default priority to Medium");
                    }
                }
            }
            catch (InvalidPluginExecutionException)
            {
                throw; // Re-throw business exceptions
            }
            catch (Exception ex)
            {
                tracingService.Trace("Error: {0}", ex.ToString());
                throw new InvalidPluginExecutionException(
                    $"An error occurred in SetDefaultPriority: {ex.Message}", ex);
            }
        }
    }
}
```

## PluginBase Abstract Class (Recommended for New Projects)

The `PluginBase` class is generated by `pac plugin init` or **Power Platform Tools for Visual Studio**. It reduces boilerplate by extracting service resolution:

```csharp
using Microsoft.Xrm.Sdk;

namespace Contoso.Plugins
{
    // PluginBase handles IServiceProvider resolution
    public class SetDefaultPriority : PluginBase
    {
        public SetDefaultPriority(string unsecure, string secure)
            : base(typeof(SetDefaultPriority)) { }

        // Override ExecuteDataversePlugin instead of implementing Execute directly
        protected override void ExecuteDataversePlugin(ILocalPluginContext localPluginContext)
        {
            var context = localPluginContext.PluginExecutionContext;
            var service = localPluginContext.OrgSvcFactory
                .CreateOrganizationService(context.UserId);
            var tracingService = localPluginContext.TracingService;

            if (context.InputParameters.Contains("Target")
                && context.InputParameters["Target"] is Entity target)
            {
                if (!target.Contains("contoso_priority"))
                {
                    target["contoso_priority"] = new OptionSetValue(100000001);
                }
            }
        }
    }
}
```

## When to Use Plugins vs Alternatives

| Scenario | Use | Why |
|---|---|---|
| Synchronous validation before save | **Plugin (Pre-Validation/Pre-Operation)** | Real-time, blocks save on failure |
| Auto-numbering on create | **Plugin (Pre-Operation)** | Set value before record commits |
| Complex calculated fields | **Plugin (Post-Operation sync)** | Runs after save, same transaction |
| Cascading updates to child records | **Plugin (Post-Operation async)** | Avoid timeout on large datasets |
| Long-running process (>2 min) | **Power Automate** | Plugins have 2-minute timeout |
| Orchestrate multiple external systems | **Power Automate** | Built-in connectors, retry, monitoring |
| Reusable API callable from apps | **Custom API + Plugin** | Typed inputs/outputs, callable from anywhere |
| Complex business logic from Code App | **Custom API** | Better than raw HTTP from client |
